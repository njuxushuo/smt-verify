# 阶段二需求文档：Symbolic Shape、Shape Constraints 与 Shape Reduction

## 1. 阶段目标

本阶段在阶段一已经完成的 `StageSpec` 输入契约基础上，实现 **Shape Constraint Modeling and Shape Reduction**。

阶段二的目标是：

> 给定一个合法的 `StageSpec`，把各 tensor 的 concrete shape 暂时转换为 symbolic shape，根据 operator、relation、world size 等信息生成 shape 约束，并使用 Z3 在满足所有约束的前提下求一个尽可能小的 reduced concrete shape。

阶段二只处理 shape，不处理 tensor value。

本阶段完成后，项目应具备如下链路：

```text
Stage JSON
   ↓
load_stage()
   ↓
StageSpec
   ↓
symbolic shape creation
   ↓
shape constraints
   ↓
Z3 Optimize
   ↓
ReducedShapeResult
```

后续阶段三将基于 `ReducedShapeResult` 为每个 reduced tensor element 创建 Z3 symbolic value，并实现 operator value semantics。

---

## 2. 参考实现：TrainVerify

本阶段的核心思想允许并鼓励参考 Microsoft TrainVerify。

论文：

`https://arxiv.org/pdf/2506.15961`

官方仓库：

`https://github.com/microsoft/TrainVerify`

重点阅读：

```text
Verdict/verdict/stage/rxshape.py
Verdict/verdict/operators/registered_ops.py
```

尤其需要理解 TrainVerify 的以下思想：

1. 为 tensor dimension 创建 Z3 Int symbolic variable；
2. 通过 lineage / sub-shape 关系约束 single tensor 与 parallel tensor shape；
3. 使用 operator 的 `infer_rxshape(...)` 传播 shape；
4. 强制每个 symbolic dimension `>= 1`；
5. 使用 Z3 `Optimize`；
6. 最小化所有 symbolic dimensions 的总和；
7. 最终将 solver model concretize 成 reduced shapes。

但是：

> 本阶段不是复制 TrainVerify 代码。

必须只借鉴其思想和关键实现机制，并按照本项目自己的 `StageSpec`、`Replicate / Shard / Partial` relation 语义进行实现。

TrainVerify 中与以下内容相关的冗余逻辑，本阶段不需要：

- TrainVerify 自己的 DFG / Node / Tensor / Lineage 数据结构；
- stage partition；
- weight reduction 特殊 shortcut；
- Config backend abstraction；
- 多 shape backend；
- TrainVerify graph frontend；
- symbolic tensor value execution；
- end-to-end lineage equality checking；
- 任何与当前 `StageSpec` 无关的兼容逻辑。

## 3. 本阶段固定设计决策

### 3.1 Solver

使用 `z3-solver`，symbolic dimension 使用 `z3.Int`。

### 3.2 Optimization

使用：

```python
z3.Optimize()
```

目标固定为：

\[
\min \sum_T \sum_i D_{T,i}
\]

即最小化所有 tensor symbolic dimensions 的总和。

本阶段不优化 tensor element count、shape product、estimated SMT cost 或其他复杂目标。

### 3.3 原始 StageSpec 不修改

Shape reduction 不允许原地修改 `StageSpec`，必须返回新的 `ReducedShapeResult`。

### 3.4 当前支持的 shape semantics

阶段二第一版正式支持 operator：

```text
matmul
add
mul
```

正式支持 relation：

```text
replicate
shard
partial
```

阶段一允许但阶段二暂未实现 shape semantics 的 operator：

```text
transpose
reshape
sum
all_reduce
all_gather
reduce_scatter
```

如果 Stage 中出现这些 operator，阶段二必须明确失败并抛出 `UnsupportedShapeSemanticsError`，不能静默忽略。

## 4. 阶段二生成的约束类型

本阶段固定生成四类约束。

### 4.1 Dimension Validity Constraints

对每个 symbolic tensor dimension：

\[
d \ge 1
\]

single 与所有 distributed rank tensor 都必须生成 validity constraints。

### 4.2 Relation Shape Constraints

这些 constraint 既用于 `input_relations`，也用于 `output_relation`。

#### Replicate

要求：

\[
shape(X_r)=shape(X_s)
\]

对所有 rank 逐维相等。

#### Shard(dim=d)

当前只支持阶段一定义的 regular contiguous equal-size shard。

若 world size 为 \(P\)，则：

对所有非 shard 维：

\[
X_{r,k}=X_{s,k}
\]

对 shard 维：

\[
P\cdot X_{r,d}=X_{s,d}
\]

并显式添加：

\[
X_{s,d}mod P=0
\]

#### Partial(sum)

阶段二只编码 shape：

\[
shape(X_r)=shape(X_s)
\]

不编码 tensor value 的：

\[
X_s=\sum_r X_r
\]

### 4.3 Operator Shape Constraints

#### MatMul

本阶段只支持二维 MatMul。

若：

```text
C = matmul(A, B)
```

则要求 rank(A)=rank(B)=rank(C)=2，并添加：

\[
A_1=B_0
\]

\[
C_0=A_0
\]

\[
C_1=B_1
\]

规则作用于 single side 和每一个 distributed rank。

#### Add

第一版只支持 element-wise same-shape add，不支持 broadcasting：

\[
shape(A)=shape(B)=shape(C)
\]

#### Mul

与 Add 相同，只支持 element-wise same-shape mul。

### 4.4 Partition / Divisibility Constraints

主要服务于 Shard：

\[
D_{global}mod world\_size=0
\]

当前阶段不单独从原始 concrete full/sub shape 推导 arbitrary ratio constraints。

即：

> 本项目当前优先使用显式 relation 语义描述 single ↔ distributed tensor shape 关系，而不是完全照搬 TrainVerify 的 generic lineage ratio inference。

未来如果支持复杂 layout / arbitrary slice，再考虑增加 generic ratio-preserving constraint。

---

## 5. 与 TrainVerify 的对应关系

```text
TrainVerify                          本项目
---------------------------------------------------------
Lineage / sub-shape          <->     Relation shape constraints
infer_rxshape(op)            <->     Operator shape constraints
d >= 1                       <->     Dimension validity
slice divisibility           <->     Shard divisibility
Optimize sum(shape)          <->     Optimize sum(shape)
```

最大的区别：

TrainVerify 主要根据 full concrete shape、sub concrete shape 和 lineage 推导 symbolic full/sub shape 比例。

本项目当前直接从：

```text
Replicate
Shard(dim)
Partial
```

生成显式 shape relation。

因此不要在同一 relation 上同时重复生成 generic original-shape ratio constraint。

---

## 6. 是否固定原始 concrete shape

阶段二的 symbolic dimension不是等于阶段一 concrete dimension。

例如阶段一：

```text
A = [4096, 11008]
```

阶段二不添加：

```text
A_D0 == 4096
A_D1 == 11008
```

否则无法 reduction。

原始 concrete shape当前主要用于：

1. 阶段一 input validation；
2. 确定 tensor rank；
3. 确定 relation / op 的结构是否合法；
4. 输出 original vs reduced 对比。

阶段二真正参与求解的是 symbolic dimensions。

## 8. `src/shape_model.py`

### 8.1 TensorRef

```python
@dataclass(frozen=True)
class TensorRef:
    scope: str
    rank: int | None
    name: str
```

约定：

```python
TensorRef(scope="single", rank=None, name="A")
TensorRef(scope="distributed", rank=0, name="A0")
```

只允许 `scope == "single"` 或 `"distributed"`。

### 8.2 SymbolicShapeBook

```python
@dataclass
class SymbolicShapeBook:
    shapes: dict[TensorRef, tuple[z3.ArithRef, ...]]
```

职责仅为保存 `TensorRef -> symbolic shape`。

### 8.3 ReducedShapeResult

```python
@dataclass
class ReducedShapeResult:
    stage_name: str
    single: dict[str, tuple[int, ...]]
    distributed: dict[int, dict[str, tuple[int, ...]]]
    objective_value: int
```

暂不增加 solver statistics。

## 9. `src/shape_constraints.py`

定义异常：

```python
class ShapeReductionError(ValueError):
    pass

class UnsupportedShapeSemanticsError(ShapeReductionError):
    pass
```

### 9.1 create_symbolic_shapes

```python
def create_symbolic_shapes(stage: StageSpec) -> SymbolicShapeBook:
    ...
```

要求：

1. 为每个 tensor dimension 创建唯一 Z3 Int；
2. symbolic variable 名称稳定、可读；
3. 不依赖 Python object id。

命名规则：

single：

```text
single__A__d0
single__A__d1
```

distributed：

```text
rank0__A0__d0
rank1__A1__d0
```

### 9.2 build_shape_constraints

```python
def build_shape_constraints(
    stage: StageSpec,
    shapes: SymbolicShapeBook,

    ...
```

必须按以下逻辑生成：

1. dimension validity；
2. input relation constraints；
3. single operator constraints；
4. distributed rank operator constraints；
5. output relation constraints；
6. shard divisibility constraints。

### 9.3 relation helper

```python
def _relation_constraints(
    stage: StageSpec,
```

### 9.4 operator helper

## 10. `src/shape_reducer.py`

提供：

```python
def reduce_shapes(stage: StageSpec) -> ReducedShapeResult:
    ...
```

固定流程：

```text
create_symbolic_shapes(stage)
        ↓
build_shape_constraints(stage, shapes)
        ↓
Optimize
        ↓
add constraints
        ↓
minimize sum(all dimensions)
        ↓
check
        ↓
model
        ↓
concretize
        ↓
ReducedShapeResult
```

### 10.1 Constraint simplification

允许参考 TrainVerify，在加入 Optimize 前对 constraints 做：

```python
z3.simplify(...)
```

并做轻量去重。

不要引入 TrainVerify 的额外 tactic pipeline，不需要 `lia2pb` 等复杂优化。

### 10.2 Objective

固定：

```python
objective = z3.Sum(all_dimension_variables)
opt.minimize(objective)
```

### 10.3 Solver result

如果 sat，返回 `ReducedShapeResult`。

如果 unsat：

```text
ShapeReductionError("shape constraints are unsatisfiable for stage '<name>'")
```

如果 unknown：

```text
ShapeReductionError("shape reduction returned unknown for stage '<name>'")
```

不要使用 assert。

## 20. 最终验收标准

阶段二完成后，系统必须能够：

```text
StageSpec
   ↓
create symbolic dimensions
   ↓
generate:
  - validity constraints
  - relation constraints
  - operator constraints
  - divisibility constraints
   ↓
Z3 Optimize
   ↓
minimum legal shapes
   ↓
ReducedShapeResult
```

核心标准 case：

```text
A [4,8], B [8,4], world_size=2
```

必须 reduce 为：

```text
A [1,2]
B [2,1]
C [1,1]
local tensors [1,1]
```

large case：

```text
A [4096,11008], B [11008,4096], world_size=8
```

必须 reduce 为：

```text
A [1,8]
B [8,1]
C [1,1]
local tensors [1,1]
```

并且所有阶段一测试继续通过。

本阶段最终交付的是：

> **一个 relation-aware、operator-aware 的 symbolic shape reduction engine，为阶段三 reduced tensor symbolic execution 提供小规模、结构合法的 concrete shapes。**

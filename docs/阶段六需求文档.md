# 阶段六需求文档：Certified Lemma Materialization MVP

## 0. 阶段定位

阶段六不是新的证明阶段，而是当前单条 Stage 验证流水线的最后一步：

> **当 Stage 5 已经对当前 Stage JSON 中唯一给定的 `output_relation` 完成 SMT certification 后，如果结果为 `PROVED`，则将这次成功证明固化为一个结构化、可持久化的 certified lemma；如果结果为 `DISPROVED` 或 `UNKNOWN`，则不生成 lemma。**

当前完整单条流水线：

```text
Stage JSON
    ↓
Stage 1: load + static validation
    ↓
Stage 2/4.5/5: soundness-aware shape reduction
    ↓
Stage 3: symbolic execution
    ↓
Stage 4: relation encoding
    ↓
Stage 5: SMT certification
    ↓
Stage 6:
    PROVED      -> materialize + persist lemma
    DISPROVED   -> no lemma
    UNKNOWN     -> no lemma
```

外部候选生成/调度不属于 Stage 6。

未来外部系统如果有多个候选 relation，应为每个候选生成独立 Stage JSON，并让每个 JSON 从 Stage 1 开始完整走到 Stage 6。

例如：

```text
candidate_1.json -> output_relation = Replicate(C)
candidate_2.json -> output_relation = Shard(C, dim=0)
candidate_3.json -> output_relation = Partial(C, sum)
```

每个 JSON 独立执行：

```text
Stage 1 -> ... -> Stage 5 -> Stage 6
```

Stage 6 本身不接收 candidate list，不循环多个 relation，也不负责 candidate ranking/filtering。

核心原则保持：

> 阶段用于规划开发顺序，源码按长期语义职责组织。

# 2. Stage 6 的职责边界

Stage 6 只负责三件事：

```text
1. 获取当前 Stage 的 Stage 5 verification result
2. PROVED 时构造 CertifiedLemma
3. 将 CertifiedLemma 持久化
```

不负责：

```text
candidate generation
candidate enumeration
multiple candidate scheduling
candidate filtering
relation synthesis
lemma matching
lemma reuse
lemma generalization
cross-stage composition
whole-graph reasoning
```

# 4. `CertifiedLemma` 数据结构

建议放在：

```text
src/lemma.py
```

定义：

```python
@dataclass(frozen=True)
class CertifiedLemma:
    lemma_id: str
    source_stage_name: str
    world_size: int

    input_relations: tuple[RelationSpec, ...]
    single_ops: tuple[OpSpec, ...]
    distributed_ops: dict[int, tuple[OpSpec, ...]]
    output_relation: RelationSpec

    original_single_shapes: dict[str, tuple[int, ...]]
    original_distributed_shapes: dict[int, dict[str, tuple[int, ...]]]

    reduced_shapes: ReducedShapeResult
```

说明：

- 当前 lemma 是 **concrete certified lemma**；
- 不做 alpha-renaming；
- 不做 shape parameterization；
- 不做 world-size generalization；
- 不做 arbitrary graph pattern abstraction；
- 但其 body 必须是结构化字段，而不是简单复制原 Stage JSON 字符串。

---

# 5. 为什么 lemma 需要保存这些内容

Stage 6 第一版的 lemma 既是：

```text
proof artifact
```

也是未来 lemma generalization / reuse 的输入。

因此至少要保留：

```text
input relation pattern
operator structure
output relation
original shape metadata
reduced proof instance
world_size
source stage identity
```

例如当前 MatMul case，应能够结构化表示：

```text
Inputs:
  A -> Shard(dim=1)
  B -> Shard(dim=0)

Single:
  MatMul(A, B) -> C

Distributed:
  rank r:
    MatMul(Ar, Br) -> Cr

Output:
  C -> Partial(sum)
```

不要只保存：

```text
"status": "PROVED"
```

否则它只是 verification log，不是 lemma。

---

# 6. `lemma_id`

Stage 6 需要稳定、可复现的 lemma ID。

建议不要使用：

```text
random UUID
timestamp
Python hash()
```

因为这些不能稳定复现。

建议基于 canonical semantic content 计算：

```python
sha256(canonical_json_bytes).hexdigest()
```

并取完整 hash 或固定前缀。

推荐：

```text
lemma_<first 16 hex chars>
```

例如：

```text
lemma_4f82d91a0a672e1c
```

canonical content 至少包含：

```text
world_size
input_relations
single_ops
distributed_ops
output_relation
original shapes
```

不建议把：

```text
source_stage_name
reduced_shapes
```

加入 identity hash。

原因：

- `source_stage_name` 只是来源元数据；
- reduced shape 是 verifier 的 proof witness/config result；
- lemma identity 应主要由 original semantic Stage pattern 决定。

当前仍然是 concrete identity，不是 generalized identity。

# 7. Canonical serialization

在 `src/lemma.py` 中建议提供：

```python
def lemma_to_dict(lemma: CertifiedLemma) -> dict:
    ...
```

以及必要的 helper，将已有 dataclass 转成 JSON-safe primitive：

```text
tuple -> list
int keys -> string or sorted list representation
RelationSpec -> dict
OpSpec -> dict
ReducedShapeResult -> dict
```

要求：

```python
json.dumps(
    payload,
    sort_keys=True,
    separators=(",", ":"),
)
```

用于 deterministic identity / persistence。

不要依赖 dataclass `repr()` 做 hash。

# 8. Lemma 构造 API

建议：

```python
def build_certified_lemma(
    stage: StageSpec,
    verification: VerificationResult,
) -> CertifiedLemma:
    ...
```

要求：

## 8.1 只有 PROVED 可以构造

如果：

```python
verification.status is not VerificationStatus.PROVED
```

必须抛：

```python
LemmaMaterializationError
```

例如：

```python
class LemmaMaterializationError(ValueError):
    pass
```

不能允许：

```text
DISPROVED
UNKNOWN
```

生成 lemma。

---

## 8.2 Stage identity 必须一致

检查：

```python
verification.stage_name == stage.name
```

否则抛：

```python
LemmaMaterializationError
```

---

## 8.3 Verification result 必须是完整 PROVED result

至少验证：

```text
counterexample is None
reason_unknown is None
```

如果状态为 PROVED 但 result 内部数据自相矛盾，拒绝 materialization。

Stage 6 不重新调用 SMT 来“二次证明”。

# 9. `certify_stage()` Pipeline API

建议新增一个 orchestration API：

```python
def certify_stage(
    stage: StageSpec,
    *,
    timeout_ms: int | None = None,
) -> CertificationResult:
    ...
```

不要修改 Stage 5 `verify_stage()` 的职责。

建议返回：

```python
@dataclass(frozen=True)
class CertificationResult:
    verification: VerificationResult
    lemma: CertifiedLemma | None
```

语义：

```text
PROVED:
  lemma != None

DISPROVED:
  lemma is None

UNKNOWN:
  lemma is None
```

内部：

```python
verification = verify_stage(stage, timeout_ms=timeout_ms)

if verification.status is PROVED:
    lemma = build_certified_lemma(stage, verification)
else:
    lemma = None

return CertificationResult(...)
```

这就是 Stage 6 的核心逻辑。

# 10. 不要让 Stage 6 自己重复 Stage 1～5

`certify_stage()` 可以调用：

```python

```

```text

```


避免第二套 verification pipeline。

从 CLI 层看：

```text

```

内部自然完整执行 Stage 1～6。

# 12. Persistence 的幂等性

如果同一个 Stage JSON 被重复 certification：

```text

```

第二次不应报错，也不应生成新 ID。

即：

```text
same semantic lemma
→ same lemma_id
→ same file
```

这是 Stage 6 必须具备的基本属性。

# 19. Stage 6 当前 lemma 的语义

Stage 6 生成的是：

> **由 Stage 5 在当前 supported-fragment reduction soundness contract 下认证过的 concrete Stage lemma。**

逻辑上：

```math
R_in
∧
Sem(G_s)
∧
Sem(G_d)
⇒
R_out
```

其中 Stage 3 使用 expression substitution，因此实际 artifact 不需要显式存一份 `Sem(...)` 公式。

可以把 lemma 理解成：

```text
given:
  input relation pattern
  operator structure

certified:
  output relation
```

---

# 20. 当前不做 generalization

第一版必须保留 concrete：

```text
tensor names
world_size
operator sequence
concrete original shapes
rank-specific distributed ops
```

不要在 Stage 6 中自动把：

```text
A/A0/A1
```

改写成：

```text
X/X_rank
```

不要把：

```text
world_size = 2
```

泛化成：

```text
arbitrary P
```

也不要把具体 shape：

```text
[4,8]
```

泛化成符号：

```text
[M,K]
```

这些是后续 lemma generalization 阶段的研究内容。

---

# 21. 当前不做 lemma lookup/reuse

Stage 6 只：

```text
create
serialize
persist
```

不实现：

```text
find_matching_lemma(stage)
reuse_lemma(stage)
skip_smt_if_hit
subgraph matching
alpha-equivalence
semantic matching
```

唯一允许的“lookup”是 `save_lemma()` 为保证幂等性检查：

```text
same lemma_id file 是否已存在
```

这不是 lemma reuse。

# 28. 验收标准

Stage 6 可判定 PASS，当且仅当：

1. 不定义新的 candidate 输入格式；
2. 继续使用现有 Stage JSON；
3. 一个 JSON 只处理一个 `output_relation`；
4. `certify_stage()` 复用 Stage 5 `verify_stage()`；
5. PROVED 时构造且只构造一个 `CertifiedLemma`；
6. DISPROVED 时 lemma 为 None；
7. UNKNOWN 时 lemma 为 None；
8. 非 PROVED result 不能直接 materialize；
9. lemma 保存完整 Stage semantic body 和 proof metadata；
10. lemma ID deterministic；
11. 相同 semantic Stage 重复执行得到相同 ID；
12. lemma persistence 幂等；
13. 不允许 silent overwrite conflicting content；
14. correct fixture 真实产生 lemma JSON；
15. wrong fixture 不产生 lemma JSON；
16. Stage 1～5 所有旧测试继续通过；
17. 未实现 candidate scheduler / lemma reuse / generalization。

# 29. 阶段六完成后的整体架构

单个 candidate 的完整流程：

```text
Stage JSON
(output_relation = one candidate)
        ↓
Stage 1
static legality
        ↓
Stage 2/4.5/5
soundness-aware shape reduction
        ↓
Stage 3
symbolic execution
        ↓
Stage 4
relation encoding
        ↓
Stage 5
SMT certification
        ↓
        ├── DISPROVED
        │      ↓
        │   no lemma
        │
        ├── UNKNOWN
        │      ↓
        │   no lemma
        │
        └── PROVED
               ↓
Stage 6
CertifiedLemma
               ↓
filesystem persistence
```

未来外部 candidate generator：

```text
candidate generator
    ↓
JSON_1   JSON_2   JSON_3 ...
    ↓       ↓       ↓
Stage1-6 Stage1-6 Stage1-6
```

因此 Stage 6 的定位非常明确：

> **Stage 6 不寻找 lemma，而是把一次已经成功的 Stage SMT proof 转换成一个稳定、结构化、持久化的 certified lemma artifact。**

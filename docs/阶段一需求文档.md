# 阶段一需求文档：Stage 输入描述、解析与合法性校验

## 1. 阶段目标

本阶段只实现 SMT Verifier 的**输入契约层**。

整个项目最终目标是验证单机程序与分布式程序之间的语义等价性，但当前阶段不实现 SMT 求解、shape reduction、symbolic tensor、operator 数学展开、relation SMT encoding、candidate enumeration 或 lemma cache。

阶段一的唯一目标是：

> 定义一种稳定、清晰、可人工编写、可程序解析、可严格校验的 Stage 输入格式，并把输入文件解析成项目内部的结构化对象。

阶段一完成后，后续阶段应能够直接读取一个 Stage 输入文件，并获得以下信息：

- 当前 case 名称；
- world size；
- 单机侧 tensor；
- 单机侧顺序 operator；
- 分布式每个 rank 上的 tensor；
- 分布式每个 rank 上的顺序 operator；
- 已知输入 tensor relation；
- 一个待验证的输出候选 relation。

当前输入只用于 SMT 原型，不绑定任何真实框架 IR。未来接入 Torch FX、nnScaler、DTensor 或其他前端时，可以增加转换层，将真实 IR 转换成当前 Stage 输入格式。

---

## 2. 本阶段固定设计决策

以下内容已经确定，Codex 不需要重新选择或讨论。

### 2.1 输入格式

使用 JSON。当前不使用 YAML，不设计自定义 DSL。

### 2.2 Operator 执行模型

Stage 中 operator 使用顺序列表表示，并按列表顺序执行。本阶段不实现 DAG、拓扑排序、控制流或真实计算图 IR。

### 2.3 Rank 描述方式

当前输入文件显式列出每个 rank：`0 ... world_size-1`。不使用 symbolic rank。后续 SMT 内部是否采用 symbolic rank，不影响当前输入协议。

### 2.4 当前支持的 Relation

阶段一固定接受：

- `replicate`
- `shard`
- `partial`

其中：

- `replicate` 不需要额外参数；
- `shard` 必须包含 `dim`；
- `partial` 必须包含 `reduce_op`，当前只允许 `sum`。

### 2.5 当前支持的 Operator 名称

阶段一只识别：

- `add`
- `mul`
- `matmul`
- `transpose`
- `reshape`
- `sum`
- `all_reduce`
- `all_gather`
- `reduce_scatter`

阶段一不实现这些 operator 的数学语义，只检查名称和 tensor 引用是否合法。

## 3. Stage JSON 顶层结构

```json
{
  "name": "...",
  "world_size": 2,
  "single": {
    "tensors": {},
    "ops": []
  },
  "distributed": {
    "ranks": {}
  },
  "input_relations": [],
  "output_relation": {}
}
```

以上字段全部必填。

---

## 4. 字段详细定义

### 4.1 `name`

类型：`string`。

要求：

- 非空；
- 用于标识当前验证 case；
- 本阶段不额外限制字符集合。

示例：

```json
"name": "matmul_shard_to_partial"
```

### 4.2 `world_size`

类型：`integer`。

要求：

- `world_size >= 1`；
- `distributed.ranks` 必须恰好包含 `"0" ... str(world_size-1)`；
- 不允许缺失或额外 rank。

---

## 5. Tensor 描述

Tensor 使用：

```json
"A": {
  "shape": [4, 8]
}
```

### 5.1 Tensor 名称

由 `tensors` 字典 key 决定。

要求：

- 非空字符串；
- 同一 scope 内唯一；
- 单机和各 rank 可以使用不同名称，例如 `A`、`A0`、`A1`。

### 5.2 `shape`

类型：`list[int]`。

要求：

- 至少一维；
- 每一维必须为整数；
- 每一维 `> 0`；
- `bool` 不视为合法整数维度。

当前不支持 symbolic dimension、`None`、`-1` 或 dynamic shape。

---

## 6. Operator 描述

每个 operator 固定采用：

```json
{
  "type": "matmul",
  "inputs": ["A", "B"],
  "outputs": ["C"]
}
```

必填字段：`type`、`inputs`、`outputs`。

### 6.1 `type`

必须属于阶段一支持的 operator 集。

阶段一不解析 operator-specific attribute，因此暂不支持 transpose 维度、reshape target shape、sum dim 等额外参数。这些在后续 operator semantics 阶段扩展。

### 6.2 `inputs`

类型：`list[string]`。

要求：

- 至少一个 tensor；
- `single.ops` 只能引用 `single.tensors`；
- rank r 的 op 只能引用该 rank 自己的 tensors；
- 本阶段不允许跨 rank tensor 引用。

### 6.3 `outputs`

类型：`list[string]`。

要求：

- 至少一个 output；
- 每个 output 必须已在当前 scope 的 `tensors` 中声明；
- operator 不隐式创建 tensor。

---

## 7. 单机侧描述

```json
"single": {
  "tensors": {
    "...": {"shape": [...]}
  },
  "ops": []
}
```

要求：

- `tensors` 必须非空；
- `ops` 必须是 list；
- `ops` 可以为空；
- op 按列表顺序解释。

---

## 8. 分布式侧描述

```json
"distributed": {
  "ranks": {
    "0": {
      "tensors": {},
      "ops": []
    },
    "1": {
      "tensors": {},
      "ops": []
    }
  }
}
```

要求：

- `ranks` 非空；
- rank key 必须严格为 `"0" ~ str(world_size-1)`；
- 每个 rank 必须包含 `tensors` 和 `ops`；
- 每个 rank 的 `tensors` 非空；
- 每个 rank 的 `ops` 可以为空。

---

## 9. Relation 描述

`input_relations` 与 `output_relation` 采用统一基础字段：

```json
{
  "single_tensor": "A",
  "distributed_tensors": ["A0", "A1"],
  "type": "shard"
}
```

### 9.1 `single_tensor`

必须引用 `single.tensors` 中已存在 tensor。

### 9.2 `distributed_tensors`

类型：`list[string]`。

要求：

- 长度严格等于 `world_size`；
- 顺序严格对应 rank；
- 第 r 项必须存在于 `distributed.ranks[str(r)].tensors`。

### 9.3 `replicate`

格式：

```json
{
  "single_tensor": "X",
  "distributed_tensors": ["X0", "X1"],
  "type": "replicate"
}
```

要求：

- 不允许 `dim`；
- 不允许 `reduce_op`；
- 所有 distributed tensor shape 与 single tensor 完全一致。

### 9.4 `shard`

格式：

```json
{
  "single_tensor": "A",
  "distributed_tensors": ["A0", "A1"],
  "type": "shard",
  "dim": 1
}
```

要求：

- `dim` 必须存在；
- `dim` 是 int 且不是 bool；
- `0 <= dim < rank(single_tensor)`；
- 不允许 `reduce_op`；
- single tensor 的 shard 维必须可被 `world_size` 整除；
- 每个 distributed tensor 与 single tensor rank 相同；
- 非 shard 维完全相同；
- shard 维等于 single shard dimension / world_size。

阶段一只支持 regular contiguous equal-size shard。当前不显式保存 offset，后续 SMT semantics 按 rank 自动计算范围。

### 9.5 `partial`

格式：

```json
{
  "single_tensor": "C",
  "distributed_tensors": ["C0", "C1"],
  "type": "partial",
  "reduce_op": "sum"
}
```

要求：

- 不允许 `dim`；
- `reduce_op` 必须为 `sum`；
- 每个 distributed tensor shape 与 single tensor 完全一致。

当前 Partial(sum) 的语义约定为：`single_tensor = sum(all rank local tensors)`。

---

## 10. Input Relations

`input_relations` 必须为 list，可以为空。

额外要求：

> 同一个 `single_tensor` 在 `input_relations` 中最多出现一次。

暂不允许同一 tensor 同时声明多个 relation。

---

## 11. Output Relation

阶段一固定只允许一个候选输出 relation，字段名为：

```text
output_relation
```

不使用数组。候选枚举将在后续阶段实现。

---

## 14. `src/stage_model.py`

职责：定义 Stage 输入解析后的内部数据对象。

使用 Python `dataclasses`，不要引入 Pydantic。

需要定义：

### `TensorSpec`

```python
name: str
shape: tuple[int, ...]
```

### `OpSpec`

```python
type: str
inputs: tuple[str, ...]
outputs: tuple[str, ...]
```

### `ProgramSpec`

```python
tensors: dict[str, TensorSpec]
ops: tuple[OpSpec, ...]
```

### `RelationSpec`

```python
single_tensor: str
distributed_tensors: tuple[str, ...]
type: str
dim: int | None = None
reduce_op: str | None = None
```

### `StageSpec`

```python
name: str
world_size: int
single: ProgramSpec
distributed: dict[int, ProgramSpec]
input_relations: tuple[RelationSpec, ...]
output_relation: RelationSpec
```

内部 `distributed` key 使用整数 rank，loader 负责把 JSON 字符串 key 转为 int。

---

## 15. `src/stage_loader.py`

职责：读取 JSON 并转换成上述 dataclass。

提供：

```python
def load_stage(path: str | Path) -> StageSpec:
    ...
```

行为：

1. UTF-8 打开 JSON；
2. JSON syntax error 时抛 `StageInputError`；
3. dictionary 转换为 `StageSpec`；
4. 调用 `validate_stage(stage)`；
5. validation 成功后返回 `StageSpec`。

同时定义项目异常：

```python
class StageInputError(ValueError):
    pass
```

所有输入格式或 validation 错误统一转换为 `StageInputError`，错误信息要指出具体字段、rank、tensor 或 relation，不直接暴露 KeyError、IndexError 等低层异常。

示例错误：

```text
rank count mismatch: world_size=2, found ranks=[0]
```

```text
input_relations[0]: shard dim 2 is out of range for tensor A with rank 2
```

## 17. 必须实现的 Validation Rules

### Stage 基础

- name 非空；
- world_size >= 1；
- distributed rank 集严格等于 `{0, ..., world_size-1}`。

### Tensor

- tensor name 非空；
- shape 至少一维；
- 每一维是 int 且不是 bool；
- 每一维 > 0。

### Program

- tensors 非空；
- ops 是合法顺序列表。

### Op

- type 属于支持列表；
- inputs 非空；
- outputs 非空；
- 所有 input/output tensor 均存在于当前 scope。

### Relation 基础

- single_tensor 存在；
- distributed_tensors 数量等于 world_size；
- 第 r 项存在于 rank r；
- type 属于 `replicate / shard / partial`。

### Replicate

- dim 为 None；
- reduce_op 为 None；
- 所有 distributed tensor shape 与 single tensor完全一致。

### Shard

- dim 存在；
- dim 是 int 且不是 bool；
- `0 <= dim < tensor rank`；
- reduce_op 为 None；
- single shard dimension 可被 world_size 整除；
- distributed tensor rank 与 single 相同；
- 非 shard 维相同；
- shard 维 = single shard dimension / world_size。

### Partial

- dim 为 None；
- reduce_op == `sum`；
- 所有 distributed tensor shape 与 single tensor完全一致。

### Input Relations

- 同一个 single tensor 最多出现一次。

## 18. `scripts/inspect_stage.py`

提供命令：

```bash
python scripts/inspect_stage.py input/matmul_shard_to_partial.json
```

行为：

1. 调用 `load_stage()`；
2. 成功时打印固定摘要；
3. 失败时打印：

```text
Validation: FAIL
Error: <message>
```

4. 成功退出码 0；
5. 失败退出码 1。

成功输出固定为：

```text
Stage: matmul_shard_to_partial
World size: 2
Single tensors: 3
Single ops: 1
Distributed ranks: 2
Distributed tensors: 6
Distributed ops: 2
Input relations:
  A -> Shard(dim=1)
  B -> Shard(dim=0)
Output relation:
  C -> Partial(sum)
Validation: PASS
```

Relation 展示规则：

- `replicate` -> `Replicate`
- `shard(dim=1)` -> `Shard(dim=1)`
- `partial(sum)` -> `Partial(sum)`

## 19. 测试要求

创建：

```text
tests/test_stage_input.py
```

使用 pytest。

至少测试以下 case：

1. **合法标准 case**：读取 `input/matmul_shard_to_partial.json`，检查 name、world_size、rank、两个 input relation 和 output relation；
2. **world_size / rank 不一致**：应抛 `StageInputError`；
3. **shape 含 0**：失败；
4. **shape 含负数**：失败；
5. **operator 引用不存在 tensor**：失败；
6. **不支持的 operator**：失败；
7. **shard dim 越界**：失败；
8. **shard local shape 不一致**：失败；
9. **shard dimension 无法被 world_size 整除**：失败；
10. **partial shape 不一致**：失败；
11. **replicate shape 不一致**：失败；
12. **distributed_tensors rank 顺序/引用错误**：失败；
13. **同一 input single tensor 重复 relation**：失败。

测试执行：

```bash
pytest -q
```

必须全部通过。

## 24. 阶段一最终验收标准

阶段一最终链路应为：

```text
JSON Stage File
      ↓
load_stage()
      ↓
StageSpec
      ↓
validate_stage()
      ↓
PASS / StageInputError
```

验收条件：

1. 标准 MatMul + Shard -> Partial case 成功读入；
2. 规定的非法 case 均被拒绝；
3. 错误信息具有明确上下文；
4. inspect 脚本输出严格符合规定格式；
5. pytest 全部通过；
6. 没有提前实现阶段二及以后内容。

本阶段最终产物不是 SMT verifier，而是：

> **一个稳定、严格、可测试的 Stage 输入契约，为后续 Shape Reduction 与 SMT Verification 提供统一输入基础。**

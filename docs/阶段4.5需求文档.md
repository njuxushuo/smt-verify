# 阶段 4.5 需求文档：Original-Shape-Aware Reduction 与 Stage Input Boundary 语义修正

## 0. 阶段定位

阶段 4.5 不是新增 verifier 功能，而是在阶段 5 正式输出 `PROVED / DISPROVED / UNKNOWN` 之前，对当前 Stage 2～4 中两个已经识别出的语义问题做一次集中修正：

1. **Shape reduction 必须从原始 concrete shape 出发并保持原始结构关系，而不是仅寻找一组满足现有约束的任意最小 shape。**
2. **Stage input relation 是当前 Stage 的 proof premise，不需要额外做 SAT/SMT 存在性检查；当前阶段只需要保证它是合法的 Stage 输入边界。跨 Stage 的 provenance/continuity 留给未来 whole-graph scheduler。**

核心原则仍然保持：

> 阶段用于规划开发顺序，源码按长期语义职责组织。

本阶段不得实现 Stage 5 verifier，不得引入 whole-graph stage scheduler，不得实现 candidate generation。

---

## 1. 当前实现中需要修正的问题

### 1.1 当前 shape reduction 的问题

当前 `src/shape_reducer.py`：

```python
shapes = create_symbolic_shapes(stage)
constraints = build_shape_constraints(stage, shapes)
optimizer.minimize(sum(all symbolic dimensions))
```

`create_symbolic_shapes()` 会为每一个 tensor 维度创建 fresh Z3 Int。

因此当前 reduction 的基本形式是：

```text
原始 concrete shapes
        ↓
只保留 rank / relation / operator symbolic constraints
        ↓
求一组最小合法 symbolic shapes
```

当前标准 `Shard` case 因为 relation 本身要求：

```text
single[d] = world_size * local[d]
```

所以能够间接保留规则等分的 `1/world_size` 比例。

但 reduction contract 仍然没有显式表达：

> reduced shape 是由 original shape 的结构关系缩减而来。

TrainVerify 风格的核心思想应抽象为：

```text
original full/sub relation
          ↓ preserve
reduced full/sub relation
```

例如：

```math
sub' / full' = sub / full
```

等价于：

```math
sub' * full = full' * sub
```

应优先使用整数交叉乘形式，避免 Z3 Real/除法。

### 1.2 当前 operator reduction 与 original shape 脱节

当前 `OperatorSemantics.shape_constraints()` 只接收 symbolic reduced shapes：

```python
shape_constraints(
    input_shapes,
    output_shapes,
    context,
)
```

它不知道 original concrete shapes。

当前仅支持：

- `matmul`
- `add`
- `mul`

对于这三个 op，当前 symbolic shape equation 本身能描述 reduced program 的合法性，但不能单独保证 original concrete program 本身合法，也没有为未来 broadcast/reshape 等 original-shape-sensitive semantics 留接口。

例如错误原始程序：

```text
A [4,8]
B [7,4]
C [4,4]
C = matmul(A,B)
```

当前 reducer 理论上可以给 fresh symbolic dimensions 重新求出一个合法 MatMul reduced instance。

阶段 4.5 后必须在 reduction 前拒绝这种 original concrete semantics 非法的程序。

### 1.3 当前 input relation 的边界检查位置偏晚

阶段 4 当前在 `relation_encoder.py` 中通过：

```python
symbolic.single.input_names
symbolic.distributed[rank].input_names
```

检查 `stage.input_relations` 是否引用 true program inputs。

这意味着：

```text
load
→ reduce
→ symbolic execute
→ relation encode
→ 才发现 input relation 引用了 stage 内部 produced tensor
```

从语义和效率上都偏晚。

Input relation 是否属于 Stage boundary 是静态 program-structure property，不依赖 symbolic value execution。

本阶段应把这类检查前移为 static Stage boundary validation。

## 2. 阶段 4.5 的目标

完成后，pipeline 应变为：

```text
Stage JSON
    ↓
load_stage()
    ↓
validate_stage()
    ├── JSON / tensor / relation metadata
    ├── concrete relation legality
    ├── concrete operator legality
    └── local Stage input-boundary legality
    ↓
shape reduction
    ├── original-shape-aware relation constraints
    └── operator reduction semantics
    ↓
symbolic execution
    ↓
relation encoding
    ↓
Stage 5 verifier
```

阶段 4.5 完成后必须满足：

### 目标 A

Reduction 不允许“修复”一个 original concrete operator 本身非法的 Stage。

### 目标 B

Relation reduction 必须明确保留 original single/local shape ratio，而不是仅依赖 relation 名称重新构造最小比例。

### 目标 C

Input relation 只作为 proof premise：

```math
R_in ⇒ R_out
```

本阶段和后续 Stage 5 **不得增加 `R_in SAT?` pre-check**。

### 目标 D

当前单 Stage 中，`input_relations` 必须引用 true program inputs。

### 目标 E

不在本阶段实现跨 Stage：

```text
Rout_i == Rin_(i+1)
```

的 provenance/continuity 检查。

该职责留给未来 whole-graph scheduler / chain validator。

## 4. 新增 `src/program_analysis.py`

目的：

> 统一保存与 program producer/input boundary 有关的静态分析，避免 `stage_validator.py` 和 `symbolic_executor.py` 分别重复实现。

定义：

```python
class ProgramAnalysisError(ValueError):
    pass
```

API：

```python
def find_program_inputs(program: ProgramSpec) -> tuple[str, ...]:
    ...
```

语义保持 Stage 3 当前实现：

- producer = 出现在某个 `op.outputs` 的 tensor；
- 没有 producer 的 declared tensor = program input；
- 保持 `program.tensors` declaration order；
- 一个 tensor 有多个 producer 时失败。

建议同时提供：

```python
def validate_program_dataflow(program: ProgramSpec, context: str) -> None:
    ...
```

至少检查：

1. multiple producers；
2. op 按声明顺序执行时 input 必须已经存在；
3. output 不允许 overwrite 已存在 tensor；
4. 最终每个 declared tensor 都必须是 input 或由 op produced。

注意：

- 这是 static program structure validation；
- 不做 Z3；
- 不执行 symbolic tensor；
- 不负责 operator shape semantics。

## 6. Operator original concrete semantics

### 6.1 扩展 `OperatorSemantics`

在 `src/operators.py` 增加：

```python
class ConcreteShapeError(ValueError):
    pass

class OperatorSemantics:
    name: str

    def validate_concrete_shapes(
        self,
        input_shapes: tuple[tuple[int, ...], ...],
        output_shapes: tuple[tuple[int, ...], ...],
        context: str,
    ) -> None:
        raise NotImplementedError

    def shape_constraints(
        self,
        input_shapes: tuple[tuple[z3.ArithRef, ...], ...],
        output_shapes: tuple[tuple[z3.ArithRef, ...], ...],
        context: str,
    ) -> list[z3.BoolRef]:
        raise NotImplementedError
```

当前阶段不强制把 original shapes 直接塞入 `shape_constraints()`，因为目前支持的 `matmul/add/mul` 在 original legality 被验证后，其 reduced structural equation 已足够。

但必须在文档中明确：

> 未来 broadcast/reshape/sum 等 original-shape-sensitive operator 可以扩展 `shape_constraints` 输入或新增 operator-specific reduction metadata；本阶段不提前设计通用框架。

这是为了保持最小设计。

### 6.2 `MatMulOperator.validate_concrete_shapes`

当前只支持 2-D：

```text
A: [M,K]
B: [K,N]
C: [M,N]
```

必须验证：

```python
len(inputs) == 2
len(outputs) == 1
rank(A) == rank(B) == rank(C) == 2
A.shape[1] == B.shape[0]
C.shape[0] == A.shape[0]
C.shape[1] == B.shape[1]
```

失败抛出 `ConcreteShapeError`，由 `stage_validator.py` 捕获并转换为 `StageInputError`。

### 6.3 Add/Mul concrete semantics

必须验证：

```text
exactly 2 inputs / 1 output
left.shape == right.shape == output.shape
```

当前不支持 broadcast。

如果 original Add/Mul 需要 broadcasting，必须拒绝，而不是由 shape reducer 自动重构。

## 7. Relation concrete semantics 重构

当前 `stage_validator.py` 仍包含：

```python
if relation.type == "replicate":
...
if relation.type == "shard":
...
partial...
```

阶段 4 时这是允许的。

阶段 4.5 为了 original-shape-aware reduction，建议完成 relation abstraction 的最后一步：

```text
RelationSemantics
├── validate_concrete_shapes()
├── shape_constraints()
└── value_constraints()
```

```python
class ConcreteRelationError(ValueError):
    pass

def validate_concrete_shapes(
    self,
    relation: RelationSpec,
    single_shape: tuple[int, ...],
    local_shapes: tuple[tuple[int, ...], ...],
    world_size: int,
    context: str,
) -> None:
    ...
```

`stage_validator.py` 负责：

```text

→ 调 get_relation(...)
→ semantics.validate_concrete_shapes(...)
→ 捕获并转换 StageInputError
```

这样 relation 的 concrete / reduced / value 三层语义都集中在 `relations.py`。

## 8. Relation original-ratio-preserving reduction

这是阶段 4.5 的核心修正。

### 8.1 修改 `RelationSemantics.shape_constraints`

签名改为：

```python
def shape_constraints(
    self,
    relation: RelationSpec,
    single_shape: tuple[z3.ArithRef, ...],
    local_shapes: tuple[tuple[z3.ArithRef, ...], ...],
    original_single_shape: tuple[int, ...],
    original_local_shapes: tuple[tuple[int, ...], ...],
    world_size: int,
    context: str,
) -> list[z3.BoolRef]:
    ...
```

`shape_constraints.py` 在调用 relation semantics 时必须同时解析：

- symbolic reduced shapes；
- StageSpec 中的 original concrete shapes。

### 8.2 通用 ratio preservation

对于每个 rank、每个 dimension，原始：

```math
single = F
local = S
```

reduced：

```math
single' = F'
local' = S'
```

必须保持：

```math
S' / F' = S / F
```

编码成整数约束：

```math
S' * F = F' * S
```

即：

```python
local_reduced_dim * original_single_dim
==
single_reduced_dim * original_local_dim
```

禁止使用 Z3 Real division。

### 8.3 Replicate

Original concrete validation：

```text
local_shape == single_shape
```

Reduction：

- 保持 same rank；
- 每个维度保留 original ratio；
- 因为 original ratio = 1，所以自然得到：

```text
local'[d] == single'[d]
```

### 8.4 Partial(sum)

Original concrete validation：

```text
local_shape == single_shape
reduce_op == "sum"
```

Reduction：同 Replicate，通过 original ratio helper 得到 same-shape。

Value semantics 不变：

```math
single[i] = Σ local_r[i]
```

### 8.5 Shard

当前 MVP 仍只支持：

> contiguous equal-size regular shard

因此 original concrete validation 仍要求：

```text
single[d] % world_size == 0
local[d] == single[d] / world_size
other dims equal
all ranks same local shape
```

Reduction 应从 original ratio 得到：

```math
local' * original_single
=
single' * original_local
```

例如：

```text
original: 11008 / 1376 = 8
```

则：

```math
local' * 11008 = single' * 1376
```

化简后就是：

```math
single' = 8 * local'
```

因此标准 regular shard 结果与当前实现应完全一致，但 contract 明确升级为：

> ratio derived from original concrete relation。

为了维持 current regular-shard contract，可以保留显式：

```python
single_reduced_dim % world_size == 0
```

但同一公式不得在多个模块重复生成。

## 10. Stage input boundary 语义修正

### 10.1 不做 SAT pre-check

明确禁止新增：

```python
solver.add(*input_constraints)
solver.check()
```

用于判断 `R_in` 是否存在解。

Stage 局部证明命题就是：

```math
∀X_s,X_d.
R_in(X_s,X_d)
⇒
R_out(G_s(X_s), G_d(X_d))
```

Stage 5 只应检查：

```math
R_in ∧ ¬R_out
```

input relation 是 theorem premise。

### 10.2 当前阶段需要检查什么

当前 single-Stage MVP 只检查 local boundary legality：

对于每个 `stage.input_relations`：

```text
single_tensor 必须是 single program input
distributed_tensors[r] 必须是 rank r program input
```

这属于静态 program boundary property。

### 10.3 检查前移

把 Stage 4 `relation_encoder.py` 中：

```python
_validate_input_relation_boundary(...)
```

前移到 `stage_validator.py`。

内部使用：

```python
find_program_inputs(stage.single)
find_program_inputs(stage.distributed[rank])
```

不要依赖 symbolic execution。

`relation_encoder.py` 删除 `_validate_input_relation_boundary()`。

Encoding 阶段只负责：

```text
resolve symbolic tensors
→ dispatch RelationSemantics.value_constraints()
```

不再承担 Stage static boundary validation。

## 11. Cross-stage provenance：本阶段明确不实现

未来 whole-graph verifier 需要检查：

```text
Stage i output relation
         ↓
Stage i+1 input relation
```

必须保证：

1. relation 来源于 initial relation 或 prior certified output；
2. logical single tensor lineage 连续；
3. distributed rank-local tensor lineage 连续；
4. relation type 一致；
5. `Shard.dim` / `Partial.reduce_op` 等 metadata 一致；
6. 如果 relation 发生变化，必须有真实 stage/operator 负责该转换。

这类功能未来建议属于：

```text
stage scheduler
/ chain validator
/ graph verifier
```

而不是 `relation_encoder.py` 或 Stage 5 local verifier。

阶段 4.5 只需在文档中写清 contract，不创建 placeholder API。

```text

B [7,4]
```

```text

```

不得进入 `reduce_shapes()` 后被修成合法 reduced MatMul。

### 15.2 Invalid original Add/Mul

例如：

```text

B [2,4]
C [2,3]
```

必须在 Stage validation 阶段失败。

### 15.3 Invalid original relation ratio

Shard：

```text

single [4,8]
rank local [4,3]
```

必须 Stage validation 失败。

### 15.4 Produced tensor used as input relation

例如：

```text
C = add(A,B)
```

却声明：

```text
input_relations:
C ~ Replicate(C0,C1)
```

现在必须在：

```text
load_stage / validate_stage
```

阶段失败。

不应等到：

```text
execute_stage
→ encode_stage_relations
```

后才失败。

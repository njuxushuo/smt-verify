# 阶段五需求文档：Complete Stage Verifier MVP

## 0. 阶段定位

阶段五是当前项目第一次真正完成一个 **端到端 Stage SMT verifier**。

此前各阶段已经分别完成：

```text
Stage 1
Stage JSON / StageSpec / static validation

Stage 2 + 4.5
original-structure-preserving shape reduction

Stage 3
symbolic tensor execution / operator value semantics

Stage 4
input/output relation value encoding

Stage 4.5
original concrete legality + true input boundary contract
```

阶段五负责把已有组件正式组合起来：

```text
Stage JSON
    ↓
load_stage()
    ↓
reduce_shapes()
    ↓
execute_stage()
    ↓
encode_stage_relations()
    ↓
build SMT proof query
    ↓
Z3 Solver
    ↓
PROVED / DISPROVED / UNKNOWN
```

核心验证命题：

```math
∀ X_s, X_d.
R_in(X_s, X_d)
⇒
R_out(G_s(X_s), G_d(X_d))
```

实际 SMT 反例查询：

```math
R_in ∧ ¬R_out
```

阶段五不得实现 whole-graph scheduler、cross-stage provenance、candidate generation 或 lemma database。

核心原则保持：

> 阶段用于规划开发顺序，源码按长期语义职责组织。

# 1. 阶段五首先补齐 reduction soundness contract

阶段 4.5 已经解决：

1. original concrete operator shape 非法时必须在 validation 阶段拒绝；
2. relation reduction 保留 original single/local shape ratio；
3. input relation 是 Stage proof premise，而不是 SAT existence obligation。

但在正式把 reduced-shape SMT 结果解释成 original full-shape Stage correctness 之前，还需要补齐两个显式 reduction constraints。

## 1.1 Reduced dimension 必须不大于 original dimension

当前 `create_symbolic_shapes()` 已保证：

```math
d' ≥ 1
```

阶段五必须补充：

```math
d' ≤ d
```

即对 Stage 中每一个 tensor dimension：

```math
1 ≤ d' ≤ d
```

其中：

- `d`：original concrete dimension；
- `d'`：reduced symbolic dimension。

原因：

> reduced shape 必须是真正的“缩减实例”，不能只是一个满足 symbolic constraints 的任意 shape。

虽然当前 Optimize 最小化目标通常不会主动把维度放大，但 soundness contract 必须显式编码该条件，而不是依赖 optimization 的偶然行为。

建议该约束由 `shape_constraints.py` 的 Stage-level shape validity 部分统一生成。

## 1.2 MatMul contraction dimension 必须保留最小 reduction basis

对于：

```math
C[i,j] = Σ_k A[i,k]B[k,j]
```

`i/j` 属于重复 SIMD 维度；

`k` 属于 reduction dimension。

对于 reduction dimension，不能总是允许：

```math
K' = 1
```

因为长度 1 无法代表多项 aggregation 的结构。

阶段五必须对当前 `MatMulOperator` 增加：

```math
K' ≥ min(2, K)
```

其中：

- `K` 为 original concrete contraction dimension；
- `K'` 为 reduced contraction dimension。

例如：

```text
original K = 8
→ reduced K >= 2

original K = 1
→ reduced K >= 1
```

这与 TrainVerify 对 associative/commutative reduction dimension 保留最小 basis 的思想一致。

# 2. Operator shape-reduction 接口修正

当前：

```python
OperatorSemantics.shape_constraints(
    input_shapes,
    output_shapes,
    context,
)
```

只接收 reduced symbolic shapes。

为了表达：

```math
K' ≥ min(2,K)
```

阶段五应最小化地修改接口，使 operator reduction semantics 可以读取 original concrete shapes。

建议改为：

```python
def shape_constraints(
    self,
    input_shapes: tuple[tuple[z3.ArithRef, ...], ...],
    output_shapes: tuple[tuple[z3.ArithRef, ...], ...],
    original_input_shapes: tuple[tuple[int, ...], ...],
    original_output_shapes: tuple[tuple[int, ...], ...],
    context: str,
) -> list[z3.BoolRef]:
    ...
```

`shape_constraints.py` 负责同时传入：

```text
reduced symbolic operator shapes
original concrete operator shapes
```

当前：

- MatMul 使用 original `K` 产生 `K' >= min(2,K)`；
- Add/Mul 暂时不需要使用 original shape 参数，但保持同一接口。

不要建立额外的 operator reduction metadata framework。

# 3. Reduction soundness 的当前正式范围

阶段五文档必须明确：

当前只对以下 fragment 建立并采用 reduction soundness contract：

```text
Operators:
- MatMul
- Add
- Mul

Relations:
- Replicate
- regular contiguous equal-size Shard(dim)
- Partial(sum)
```

当前证明思想：

```text
pointwise / regular SIMD dimensions
    → 去除重复 index，局部计算模式保持

MatMul contraction dimension
    → 保留至少 size-2 reduction basis
    → 利用 sum 的结合律/交换律与归纳推广

relation structure
    → Stage 4.5 保持 original rank/index/shape ratio
```

因此对于当前 supported fragment，定义：

```math
Valid(S)
=
∀X_s,X_d.
R_in(X_s,X_d)
⇒
R_out(G_s(X_s),G_d(X_d))
```

目标 soundness statement：

```math
Valid(S_reduced) ⇒ Valid(S_original)
```

阶段五不要求在代码中 mechanize 这一定理。

但是必须：

1. 在代码中 enforce 当前 theorem 所依赖的 reduction constraints；
2. 在文档中明确 theorem scope、assumptions 和不覆盖的 semantics；
3. 不允许对 unsupported operator/layout 声称同样的 reduction soundness。

# 4. 新增 Stage verifier

建议新增：

```text
src/verifier.py
```

不要拆成多个 solver package。

## 4.1 VerificationStatus

定义：

```python
from enum import Enum

class VerificationStatus(str, Enum):
    PROVED = "PROVED"
    DISPROVED = "DISPROVED"
    UNKNOWN = "UNKNOWN"
```

语义：

### PROVED

Z3 返回：

```text
UNSAT
```

即：

```math
R_in ∧ ¬R_out
```

无解。

对当前 supported reduction fragment：

> candidate output relation 被认证为 original Stage correctness。

### DISPROVED

Z3 返回：

```text
SAT
```

表示存在一组满足 input relation 的 symbolic inputs，使 output relation 失败。

必须返回 counterexample。

### UNKNOWN

Z3 返回：

```text
UNKNOWN
```

包括 solver timeout 导致的 unknown。

不得把 UNKNOWN 当作：

```text
PROVED
```

或：

```text
DISPROVED
```

# 5. VerificationResult

建议：

```python
@dataclass(frozen=True)
class VerificationResult:
    stage_name: str
    status: VerificationStatus
    reduced_shapes: ReducedShapeResult
    input_constraint_count: int
    output_constraint_count: int
    counterexample: Counterexample | None = None
    reason_unknown: str | None = None
```

约束：

```text
PROVED:
counterexample is None
reason_unknown is None

DISPROVED:
counterexample is not None
reason_unknown is None

UNKNOWN:
counterexample is None
reason_unknown may be non-None
```

不要加入过多统计信息。

Stage 5 MVP 不要求：

```text
solver statistics
memory statistics
proof certificate
unsat core
proof trace
```

# 6. Counterexample 数据结构

建议新增：

```python
@dataclass(frozen=True)
class Counterexample:
    single_inputs: dict[str, tuple[str, ...]]
    distributed_inputs: dict[int, dict[str, tuple[str, ...]]]
    failed_output_constraints: tuple[int, ...]
```

只提取：

```text
program input free variables
```

不要 dump solver model 中所有内部 expression/declaration。

原因：

> counterexample 应该描述“哪一组 Stage inputs 打破 candidate relation”，而不是暴露 Z3 内部模型细节。

# 7. Counterexample 提取规则

Stage 3 中：

```text
program input = declared tensor without producer
```

其 symbolic values 是真正 free Z3 variables。

DISPROVED 时：

```python
model = solver.model()
```

对：

```text
symbolic.single.input_names
symbolic.distributed[rank].input_names
```

逐 tensor 提取：

```python
model.eval(value, model_completion=True)
```

序列化为：

```python
str(model_value)
```

当前支持 Z3 Real symbolic input，因此可能输出：

```text
0
1
-1
1/2
```

Stage 5 不需要把 rational 转为 Python float。

## 7.1 failed_output_constraints

对于：

```python
encoded.output_constraints
```

逐个做：

```python
model.eval(constraint, model_completion=True)
```

如果结果为 `False`，记录该 constraint index。

例如：

```text
failed_output_constraints = (1, 3)
```

表示 output relation 的第 1、3 个 element constraint 被反例破坏。

该字段主要用于 debugging。

# 8. SMT query 构造

这是 Stage 5 最核心的逻辑。

不得加入：

```text
R_in SAT?
```

pre-check。

直接：

```python
solver = z3.Solver()

solver.add(*encoded.input_constraints)

output_formula = z3.And(*encoded.output_constraints)

solver.add(z3.Not(output_formula))

result = solver.check()
```

对应：

```math
R_in ∧ ¬R_out
```

## 8.1 多个 output constraints 的否定方式

必须是：

```math
¬(c_0 ∧ c_1 ∧ ... ∧ c_n)
```

即：

```python
z3.Not(z3.And(*encoded.output_constraints))
```

禁止写成：

```math
¬c_0 ∧ ¬c_1 ∧ ... ∧ ¬c_n
```

因为我们需要寻找：

> 任意一个 output constraint 被破坏

而不是要求：

> 所有 output constraints 同时被破坏。

## 8.2 空 output constraints

正常合法 relation 当前不会产生空 output constraints。

但 verifier 应 defensive 地拒绝：

```text
len(encoded.output_constraints) == 0
```

建议抛：

```python
VerificationError
```

不要让：

```python
z3.And()
```

静默成为 True。

# 9. VerificationError

定义：

```python
class VerificationError(ValueError):
    pass
```

用于 verifier orchestration contract violation，例如：

```text
empty output relation constraints
invalid timeout value
```

注意：

原始 Stage 输入非法仍由已有：

```python
StageInputError
```

负责。

Shape reduction 错误仍由：

```python
ShapeReductionError
```

负责。

Symbolic execution 错误仍由：

```python
SymbolicExecutionError
```

负责。

Relation encoding 错误仍由：

```python
RelationEncodingError
```

负责。

不要把所有异常统一吞成 `VerificationError`。

# 10. `verify_stage()` API

建议：

```python
def verify_stage(
    stage: StageSpec,
    *,
    timeout_ms: int | None = None,
) -> VerificationResult:
    ...
```

内部顺序必须固定：

```text
1. validate timeout
2. reduce_shapes(stage)
3. execute_stage(stage, reduced)
4. encode_stage_relations(stage, symbolic)
5. build solver
6. optional timeout
7. add Rin
8. add Not(And(Rout))
9. solver.check()
10. map result
```

注意：

正常从：

```python
load_stage(...)
```

进入时，Stage 已经过 static validation。

`verify_stage()` 不需要再次调用：

```python
validate_stage(stage)
```

否则会造成重复职责。

如果未来直接构造 `StageSpec` 调 verifier，调用方负责先 validation。

# 11. Timeout policy

Stage 5 支持可选 timeout：

```python
timeout_ms: int | None
```

规则：

```text
None
→ 不设置 Z3 timeout

positive int
→ solver.set(timeout=timeout_ms)

0 / negative / bool / non-int
→ VerificationError
```

如果 Z3 因 timeout 返回：

```text
unknown
```

统一：

```text
status = UNKNOWN
reason_unknown = solver.reason_unknown()
```

Stage 5 MVP 不单独增加：

```text
TIMEOUT
```

状态。

原因：

> timeout 是 UNKNOWN 的一种 solver reason，不需要扩大核心 verifier status space。

CLI 可以显示：

```text
UNKNOWN (timeout)
```

但 API status 仍然是：

```text
UNKNOWN
```

# 24. 验收标准

Stage 5 可判定 PASS，当且仅当：

1. 所有 reduced dimensions 显式满足：

```math
1 ≤ d' ≤ d
```

2. MatMul contraction dimension满足：

```math
K' ≥ min(2,K)
```

3. Stage 4.5 original ratio constraints 保持有效；
4. `src/verifier.py` 完成端到端 verifier orchestration；
5. proof query 精确为：

```math
R_in ∧ ¬(∧ R_out_constraints)
```

6. 没有 `R_in SAT?` pre-check；
7. UNSAT -> PROVED；
8. SAT -> DISPROVED；
9. SAT 时提取真实 program-input counterexample；
10. UNKNOWN -> UNKNOWN，并保留 `reason_unknown`；
11. timeout 作为 UNKNOWN reason，而不是新增 TIMEOUT status；
12. 正确 candidate 端到端 PROVED；
13. 错误 candidate 端到端 DISPROVED；
14. Stage 1～4.5 所有旧测试继续通过；
15. 未实现 Stage 6 / whole-graph / candidate-generation 功能；
16. `docs/stage5_verifier.md` 清晰说明 reduction soundness scope 和 Stage proof formula。

# 25. 阶段五完成后的整体语义

阶段五完成后，我们第一次得到完整的 local Stage certification pipeline：

```text
Original Stage
    ↓
static legality
    ↓
structure-preserving shape reduction
    ↓
symbolic execution
    ↓
relation encoding
    ↓
SMT counterexample search
    ↓
UNSAT
    ↓
PROVED
```

对于当前 supported fragment：

```text
MatMul / Add / Mul
Replicate / regular Shard / Partial(sum)
```

`PROVED` 的语义定义为：

> 在 documented reduction soundness contract 下，任意满足 Stage input relation 的 original-shape single/distributed inputs，经过对应 Stage operator semantics 后都满足 candidate output relation。

# 阶段三需求文档：Symbolic Tensor 与 Operator Value Semantics

## 1. 阶段定位

本项目继续遵循：

> **阶段用于规划开发顺序，源码按长期语义职责组织。**

阶段三不是为了“新增一批 Stage 3 专属文件”，而是补齐项目中一个长期独立能力：

> **Program-level symbolic execution。**

阶段一已经完成：

```text
Stage JSON
    ↓
StageSpec
```

阶段二已经完成：

```text
StageSpec
    ↓
symbolic shape constraints
    ↓
ReducedShapeResult
```

阶段 2.5 已经完成 operator semantics 重构：

```text
OpSpec
    ↓
get_operator(op.type)
    ↓
OperatorSemantics
    ↓
operator-specific shape semantics
```

阶段三在此基础上实现：

```text
StageSpec + ReducedShapeResult
          ↓
识别 program input tensors
          ↓
为 input tensor 的每个 reduced element 创建 Z3 Real 自由变量
          ↓
按 program.ops 顺序执行
          ↓
调用同一个 OperatorSemantics 对象的 symbolic_execute(...)
          ↓
得到所有 intermediate / output tensor 的 Z3 expressions
          ↓
SymbolicStageResult
```

阶段三只负责 **单个 program 自身的计算语义**。

本阶段仍然不编码：

```text
Replicate value relation
Shard value relation
Partial value relation
single ↔ distributed equivalence
```

这些属于后续 Relation semantics 与完整 Stage verification。

---

# 2. 阶段三最终要实现的功能

阶段三完成后，对于如下 program：

```text
A
B
C
D

C = matmul(A, B)
D = add(C, C)
```

系统必须能够自动判断：

```text
A, B 没有 producer
→ A, B 是 program inputs
→ 为 A/B 的 reduced tensor elements 创建自由 Z3 Real

C 由 matmul 产生
→ C 的元素直接保存 MatMul expression

D 由 add 产生
→ D 的元素继续保存由 C expression 构成的 expression
```

例如 reduced shapes：

```text
A [1,2]
B [2,1]
C [1,1]
D [1,1]
```

应得到：

\[
A=[a_0,a_1]
\]

\[
B=[b_0,b_1]^T
\]

\[
C_{0,0}=a_0b_0+a_1b_1
\]

\[
D_{0,0}=C_{0,0}+C_{0,0}
\]

注意：

> `C` 和 `D` 不创建新的自由 symbolic variables。

它们的值直接由 operator symbolic semantics 定义。

# 3. 本阶段固定设计决策

以下设计已经确定，Codex 只负责实现。

## 3.1 Scalar symbolic type

所有 program input tensor elements 使用：

```python
z3.Real
```

即：

```text
free tensor scalar -> Z3 Real variable
```

不使用：

```text
Int
Float
BitVec
FP
```

阶段二 shape dimension 继续使用 Z3 Int，两者不要混淆。

---

## 3.2 Symbolic Tensor storage

使用项目自己的：

```python
SymbolicTensor
```

不使用 NumPy。

内部使用：

```python
shape: tuple[int, ...]
values: tuple[z3.ArithRef, ...]
```

`values` 使用 **row-major flattened storage**。

例如：

```text
shape = (2, 3)
```

对应：

```text
values = (
    x00, x01, x02,
    x10, x11, x12,
)
```

---

## 3.3 Program input tensor 的判断

一个 tensor 是否是 program input，不由 JSON 额外声明。

定义：

> **没有任何 operator 产生该 tensor，则该 tensor 是 program input。**

即先收集：

```python
produced = {
    output_name
    for op in program.ops
    for output_name in op.outputs
}
```

然后：

```python
program_inputs = [
    tensor_name
    for tensor_name in program.tensors
    if tensor_name not in produced
]
```

要求保持 `program.tensors` 原有 insertion order。

---

## 3.4 Producer 定义

若：

```text
C = matmul(A, B)
```

则：

```text
matmul op 是 C 的 producer
```

若 tensor 没有出现在任何：

```text
op.outputs
```

中，则没有 producer。

---

## 3.5 Single-assignment program semantics

阶段三正式规定：

> 同一个 tensor name 最多只能被一个 operator 产生一次。

如果两个 op 都输出：

```text
C
```

阶段三必须拒绝：

```text
SymbolicExecutionError
```

本阶段不支持：

```text
in-place update
tensor overwrite
SSA phi
mutable tensor state
```

这是当前 MVP 的固定语义。

---

## 3.6 Ordered execution / use-before-produce

`ProgramSpec.ops` 按顺序执行。

执行某个 op 时，它的所有 input tensor 必须已经存在于 symbolic environment 中。

例如：

```text
op0: D = add(C, A)
op1: C = matmul(A, B)
```

虽然 `C` 在 program.tensors 中声明，但它有 producer `op1`，因此不是 program input。

执行 `op0` 时 `C` 尚未产生，必须报：

```text
SymbolicExecutionError
```

不允许：

- 自动拓扑排序；
- 向后寻找 producer；
- 把尚未产生的 C 错误当成自由输入。

Stage 1 当前只保证 tensor reference 存在；这个 execution-order 约束由阶段三负责。

---

## 3.7 Operator value semantics

继续使用阶段 2.5 已建立的：

```text
src/operators.py
```

不得再建立第二套 central dispatch。

最终：

```text
MatMulOperator
├── shape_constraints(...)

AddOperator
├── shape_constraints(...)
└── symbolic_execute(...)

MulOperator
├── shape_constraints(...)
└── symbolic_execute(...)
```

---

## 3.8 Stage 3 支持 operator 范围

本阶段只实现：

```text
matmul
add
mul
```

阶段一声明但目前没有 shape semantics 的：

```text
transpose
reshape
sum
all_reduce
all_gather
reduce_scatter
```

仍然不在阶段三支持范围内。

由于阶段三入口首先调用阶段二 `reduce_shapes(stage)`，包含这些 operator 的 Stage 会在 shape reduction 阶段先明确失败。

不要在阶段三偷偷增加这些 operator。

# 5. `src/symbolic_tensor.py`

该文件负责长期的 symbolic tensor 数据结构。

不得负责 program traversal 或 operator dispatch。

---

## 5.1 `SymbolicExecutionError`

在该文件定义：

```python
class SymbolicExecutionError(ValueError):
    pass
```

阶段三 execution-level 错误统一使用该异常。

不要把该异常放入：

```text
shape_model.py
```

因为它已经不属于 shape reduction。

---

## 5.2 `SymbolicTensor`

定义：

```python
@dataclass(frozen=True)
class SymbolicTensor:
    shape: tuple[int, ...]
    values: tuple[z3.ArithRef, ...]
```

### Constructor validation

`__post_init__()` 必须验证：

1. `shape` 非空；
2. 每个 dimension 是正整数；
3. `len(values) == product(shape)`。

不接受零维 tensor / scalar tensor。

当前项目 Stage 1 本身也要求 tensor rank >= 1，因此保持一致。

---

## 5.3 `numel`

提供：

```python
@property
def numel(self) -> int:
    ...
```

返回：

\[
\prod_i shape_i
\]

只使用 Python 标准库，例如：

```python
math.prod
```

不要引入 NumPy。

---

## 5.4 Row-major indexing

提供：

```python
def at(self, index: tuple[int, ...]) -> z3.ArithRef:
    ...
```

例如：

```text
shape=(2,3)
index=(1,2)
```

flat offset：

\[
1\times3+2=5
\]

返回：

```text
values[5]
```

必须检查：

- index rank 与 tensor rank 相同；
- 每维 `0 <= index_i < shape_i`。

越界抛：

```text
IndexError
```

rank 不匹配也抛：

```text
IndexError
```

---

## 5.5 `SymbolicProgramResult`

定义：

```python
@dataclass
class SymbolicProgramResult:
    input_names: tuple[str, ...]
    tensors: dict[str, SymbolicTensor]
```

含义：

```text
input_names
    program 中没有 producer 的 tensor names

tensors
    symbolic execution 完成后 program 中所有 tensor 的 symbolic representation
```

要求：

```text
set(result.tensors) == set(program.tensors)
```

成功 execution 后所有 declared tensor 都必须存在。

---

## 5.6 `SymbolicStageResult`

定义：

```python
@dataclass
class SymbolicStageResult:
    stage_name: str
    single: SymbolicProgramResult
    distributed: dict[int, SymbolicProgramResult]
```

这是阶段三最终返回结果。

# 8. `MatMulOperator.symbolic_execute`

当前只支持二维 MatMul，与已有 shape semantics 完全对应。

输入：

```text
A shape = (M, K)
B shape = (K, N)
output shape = (M, N)
```

---

## 8.1 Runtime validation

必须验证：

```text
2 inputs
1 output shape
rank(A)=rank(B)=rank(C)=2
A.shape[1] == B.shape[0]
C.shape == (A.shape[0], B.shape[1])
```

若不满足：

```text
raise SymbolicExecutionError
```

不要依赖“阶段二理论上已经保证”而完全省略 runtime consistency check。

---

## 8.2 Value semantics

对每个：

```text
i ∈ [0,M)
j ∈ [0,N)
```

计算：

\[
C_{i,j}
=
\sum_{k=0}^{K-1}
A_{i,k}B_{k,j}
\]

实现必须使用：

```python
SymbolicTensor.at(...)
```

读取元素。

---

## 8.3 Sum construction

固定使用：

```python
z3.Sum(terms)
```

其中：

```python
terms = [
    A.at((i, k)) * B.at((k, j))
    for k in range(K)
]
```

因为 K >= 1，不需要处理 empty sum。

可以：

```python
z3.simplify(...)
```

output expression，但不是必须。

不要人为展开代数化简规则。

---

## 8.4 Output storage

按 row-major 顺序生成：

```text
C00, C01, ...
C10, C11, ...
```

并返回：

```python
(SymbolicTensor(shape=output_shape, values=...),)
```

---

# 9. `AddOperator.symbolic_execute`

只支持当前已有的 same-shape element-wise add。

验证：

```text
2 inputs
1 output shape
A.shape == B.shape == C.shape
```

每个 flat element：

\[
C_i=A_i+B_i
\]

直接遍历：

```python
zip(A.values, B.values)
```

生成：

```python
left + right
```

与 Add 相同。

每个 flat element：

\[

\]

生成：

```python

```

# 12. `find_program_inputs`

提供：

```python
def find_program_inputs(program: ProgramSpec) -> tuple[str, ...]:
    ...
```

逻辑：

1. 遍历全部 `op.outputs`；
2. 统计每个 tensor 的 producer 数量；
3. 若任意 tensor producer count > 1：
   ```text
   raise SymbolicExecutionError
   ```
4. 返回所有没有 producer 的 declared tensor；
5. 保持 `program.tensors` declaration order。

---

## 12.1 Multiple producer error

例如：

```text
C = add(A, B)
C = mul(A, B)
```

必须失败。

错误信息至少包含：

```text
tensor 'C'
multiple producers
```

# 13. Reduced shape consistency

提供 private helper：

```python
def _validate_reduced_shapes(
    program: ProgramSpec,
    reduced_shapes: dict[str, tuple[int, ...]],
    context: str,
) -> None:
    ...
```

要求：

```text
reduced_shapes keys
==
program.tensors keys
```

不能：

- 少 tensor；
- 多 tensor。

同时每个 reduced shape：

```text
rank == 原 TensorSpec.shape 的 rank
```

以及：

```text
每个 reduced dimension > 0
```

若不一致抛：

```text
SymbolicExecutionError
```

# 14. `execute_program`

提供：

```python
def execute_program(
    program: ProgramSpec,
    reduced_shapes: dict[str, tuple[int, ...]],
    scope_prefix: str,
    context: str,
) -> SymbolicProgramResult:
    ...
```

固定流程：

```text
_validate_reduced_shapes(...)
        ↓
find_program_inputs(program)
        ↓
为所有 program inputs 创建 SymbolicTensor free variables
        ↓
environment: dict[str, SymbolicTensor]
        ↓
按 program.ops 原顺序执行
        ↓
每个 op:
    检查所有 input 是否已经在 environment
    get_operator(op.type, op_context)
    收集 input SymbolicTensor
    从 reduced_shapes 取得 output_shapes
    semantics.symbolic_execute(...)
    检查返回 output 数量
    写入 environment
        ↓
最终检查 environment 覆盖所有 declared tensors
        ↓
SymbolicProgramResult
```

---

# 15. Use-before-produce

在执行 op 时：

```python
for input_name in op.inputs:
    if input_name not in environment:
        ...
```

必须抛：

```text
SymbolicExecutionError
```

错误中至少包含：

```text
op context
tensor name
not available / produced
```

不要自动拓扑排序。

---

# 16. Output overwrite

由于 `find_program_inputs()` 已确保每个 tensor 最多一个 producer，但 executor 仍需防御性检查：

在写：

```python
environment[output_name] = tensor
```

之前，如果：

```text
output_name 已经存在于 environment
```

则抛：

```text
SymbolicExecutionError
```

正常情况下 produced tensor 不会被初始化为 input，因此不会冲突。

---

# 17. Operator output count

执行：

```python
outputs = semantics.symbolic_execute(...)
```

后，要求：

```text
len(outputs) == len(op.outputs)
```

否则：

```text
SymbolicExecutionError
```

当前三个 operator 都返回 1 个 output。

这是 executor 与 OperatorSemantics 之间的接口契约。

---

# 18. `execute_stage`

提供：

```python
def execute_stage(
    stage: StageSpec,
    reduced: ReducedShapeResult,
) -> SymbolicStageResult:
    ...
```

要求：

1. `reduced.stage_name == stage.name`；
2. reduced distributed rank set 与 stage rank set 完全一致；
3. single：
   ```python
   execute_program(
       stage.single,
       reduced.single,
       scope_prefix="single",
       context="single",
   )
   ```
4. 每个 rank r：
   ```python
   execute_program(
       stage.distributed[r],
       reduced.distributed[r],
       scope_prefix=f"rank{r}",
       context=f"distributed.ranks[{r}]",
   )
   ```
5. 返回 `SymbolicStageResult`。

# 20. 当前标准 case 的 symbolic semantics

输入：

```text
input/matmul_shard_to_partial.json
```

阶段二结果：

```text
Single:
A [1,2]
B [2,1]
C [1,1]

Rank 0:
A0 [1,1]
B0 [1,1]
C0 [1,1]

Rank 1:
A1 [1,1]
B1 [1,1]
C1 [1,1]
```

---

## 20.1 Single inputs

没有 producer：

```text
A
B
```

创建：

```text
single__A__v0
single__A__v1

single__B__v0
single__B__v1
```

C 不创建自由变量。

---

## 20.2 Single C

必须语义等价于：

\[
C_{0,0}
=
single\_\_A\_\_v0 \times single\_\_B\_\_v0
+
single\_\_A\_\_v1 \times single\_\_B\_\_v1
\]

允许 Z3 输出不同但等价的括号/`Sum` 表示。

---

## 20.3 Rank 0

inputs：

```text
A0
B0
```

free variables：

```text
rank0__A0__v0
rank0__B0__v0
```

C0：

\[
rank0\_\_A0\_\_v0
\times
rank0\_\_B0\_\_v0
\]

---

## 20.4 Rank 1

同理：

\[
C1
=
rank1\_\_A1\_\_v0
\times
rank1\_\_B1\_\_v0
\]

---

# 21. 重要边界：阶段三不建立 single/distributed relation

阶段三结束后：

```text
single A/B/C
rank0 A0/B0/C0
rank1 A1/B1/C1
```

都是已经完成 symbolic execution 的 tensor。

但是阶段三**不添加**：

```text
A0/A1 是 A 的 shard
B0/B1 是 B 的 shard
C == C0 + C1
```

因此阶段三不能直接证明：

\[
C=C_0+C_1
\]

这是预期行为，不是缺陷。

阶段四将负责：

```text
Replicate / Shard / Partial value relation
```

# 49. 最终验收标准

阶段三完成后，标准 case 必须具备以下能力：

```text
Stage JSON
    ↓
StageSpec
    ↓
ReducedShapeResult
    ↓
single:
    A/B -> Z3 Real free symbolic tensor
    C   -> MatMul Z3 expression
    ↓
rank0:
    A0/B0 -> Z3 Real free symbolic tensor
    C0    -> local MatMul expression
    ↓
rank1:
    A1/B1 -> Z3 Real free symbolic tensor
    C1    -> local MatMul expression
```

并且：

```text
C/C0/C1 不应存在自由 output variables
```

MatMul/Add/Mul 的 symbolic semantics 必须通过 Z3 等价性测试验证。

阶段三最终交付的是：

> **一个基于 reduced concrete shapes 的 Program-level symbolic execution engine：自动识别没有 producer 的 program inputs，为其创建 element-wise Z3 Real 自由变量，并沿 operator 顺序传播 MatMul/Add/Mul 的 symbolic expressions，得到 single program 与每个 distributed rank 的完整 symbolic computation。**

它为下一阶段：

```text
Replicate / Shard / Partial value relation encoding
```

提供输入。
